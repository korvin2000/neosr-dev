# Stage-2 audit: closure matrix

Written 2026-11-10 (session 7, Windows machine). The stage-2 audit (`analysis/`, ten reports) produced 167
findings; `PLAN.md` assigned about 96 ids to lanes and nobody recorded what became of the rest. This file gives
every finding a verdict with evidence.

**Method.** One reader per report (ten parallel agents, read-only, no tests run) opened each finding, searched its
id in `PLAN.md`, `DECISIONS.md`, `PROGRESS.md`, `tests/` and the code, and read the code the finding names. A
`done` needed something read: code at `path:line` or a test by name; a sentence in `PROGRESS.md` did not count. The
main thread then checked by script that every `done` row cites something that exists (148 `path:line` and 135 test
references: all present; one row, A-18, cites a path without its folder), read a sample of `done` rows against the
code (GP-01/ST-08, A-10, D-01, L-10, MX-01) and read all 20 `open` rows. Line numbers are those of 2026-11-10
after commit ad84712; they move, the symbol names next to them do not.

**Limits.** No test was run for this matrix (CUDA-only tests could not run here at all), so `done` means "the fix
is in the code and a test for it exists", not "the test was seen passing"; the last full suite is commit 504ad50.
Speed and memory numbers were not re-measured: rows say "number unverified (needs GPU)" where a claim rests on
one. Verdicts on judgement calls are listed under "Notes" below.

| verdict | meaning |
|---|---|
| `done` | the fix (or an equivalent) is in the code; evidence cited |
| `opt-in` | implemented behind a key that is off by default; its A/B belongs to the Linux machine |
| `rejected` | deliberately not done; where and why is cited |
| `deferred` | kept with its evidence and fix; waits for a stated trigger (owner) |
| `open` | the defect is still there, or no fix and no decision was found |

## Notes on judgement calls
- **`rejected` rows that follow the report itself:** GP-09, GP-10, GP-11, GP-13 and ST-13 are findings whose own
  recommendation was "keep as is"; the code still matches. O-12 (fused AdamW) rests on one measurement in
  `analysis/gpu_profile.md` (GP-10), not on an entry in `DECISIONS.md`.
- **Shipped default-on although the report said "A/B before default":** MX-02, MX-03, MX-05 (live gradients in
  mixed archs; old checkpoints keep their forward through a remap). Read as correctness fixes under principle 1.
- **`done` with a reduced A/B:** O-11 (8k updates, one arch, one seed; `DECISIONS.md` 13 says so), L-01 / ST-01 (FDL
  0.02 on realplksr + metagan only), D-03 (one no-augmentation arm).
- **`done` with a missing sub-item:** GP-07 (no readme note recommending `compile` for transformer templates), GP-05
  (no peak-memory test), MT-08 / MT-14 / MT-15 (see the Windows list), D-14 (only the `--bits8` conversion, the
  loader is unchanged), D-06 (worker-sizing advice is thin), T-03 (a hard kill during validation still loses the
  update), W-08 (only variant a), MX-16 (state-dict manifests for three of twelve files).
- **Numbering:** `PLAN.md`, commit b5787a1 and the code comments swap the report's S-10 and S-11 (warm-up is
  ST-10, the EMA range ST-11 there); the stability table follows the report and says so in its rows. MT-06 and
  MT-14 were implemented in the trainer lane (`config.py`, `base.py`), not in the metrics lane's files.
- **Not verified here:** every CUDA-only test named as evidence (sync checks, autocast, bf16 parity) and the tests
  that need the cached DINOv2 hub repository.
