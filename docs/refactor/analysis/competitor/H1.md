## Verification of the disputed claims (read-only, CPU probe `scratchpad/h1_probe.py`)

| Claim | Result |
|---|---|
| Target MS-SSIM NaN (G5.3) | Confirmed: anti-correlated input gives loss `nan` and non-finite grad. |
| Guard placement: Fable said per-pixel `relu(cs)` as in competitor `C/mssim_loss.py:358-361`; Codex said per image/channel after the spatial mean | Codex's placement wins. pytorch-msssim applies relu after the spatial mean, not per pixel, so Fable's "does the same" is inaccurate. Probe with the guard after a per-(N,C) mean: finite, and a bad image in the batch does not zero the gradient of the good ones. With `clamp_min(0)` a fully anti-correlated image gets grad 0. With `clamp_min(1e-6)` its other scales keep a gradient (max 4.6e-6). Fable's note that `clamp_min(eps)` "keeps a tiny gradient" through the clamped term is wrong, because clamp's backward is 0 below the min. The benefit is that the product with the other scales is no longer 0. |

## Do not port

- **Competitor weighting contract**: `CM:648-661,668` multiplies `abs(loss_weight)` while CHC, consistency, Huber, HFEN, TV, ConvNeXt, DINO, Laplacian and Checkerboard also multiply internally, so their weight is applied twice (weight²). Keep the target convention: in-loss, once.
- **`SSIMLoss` / `MSSIMLoss` as replacements**: `C/mssim_loss.py:421-424` returns similarity, not `1-SSIM`, so minimizing it rewards dissimilarity. `MSSIMLoss` defaults `include_luminance=False` and `test_y_channel=True` (`:508,511`), which silently changes the objective. Per-pixel relu biases the score and zeroes gradients in anti-correlated regions. Port only the guard (item 1).
- **`MSSSIML1Loss`**: the grouped conv mixes scales across RGB (verified above). `g_masks` is a plain tensor moved to CUDA at init, `cuda_dev` is unused. The same effect comes from `mssim_loss` + `L1Loss`.
- **DISTS / LDL as claimed fixes**: alpha/beta are still trainable (G5.6). `var**0.2` NaN grad is still there (G5.1). Items 3 and 5 credit only normalization/loading and the EMA mask.
- **ConvNeXt / DINO perceptual losses**: `_extract_feats` is `@torch.no_grad()` and is used on the prediction (`C/convnext_perceptual_loss.py:118`, `C/dino_perceptual_loss.py:90`), so the loss has no gradient. DINO also assumes a square token grid, guesses patch size, and silently falls back to the last layer. The target's `T/fdl_loss.py:168-250` dinov2 path is gradient-correct. A new-backbone experiment would be a separate design, not a port.
- **`perceptual_fp16_loss` PD/FD criteria**: PD is a cumsum over unsorted raster positions (not a distribution distance) and its `1e-14` underflows in FP16. FD indexes projections by selected-loss order (`:153-159` vs `:233`), so it crashes when the first selected layer is not 64-channel. It duplicates `T/fdl_loss.py`. No PatchLoss/IPK or MSSWD fix exists in the competitor.
- **`r3gan_loss.py` as implemented**: it is relativistic-average hinge with detached means (`:233-239`), not R3GAN. The "safe" penalty fallback with `create_graph=False` makes R1/R2 a no-op (`:70-103`). It does a `.item()` sync per D step and keeps step state inside the loss. See item 10 for the rewrite.
- **`feature_matching_loss.py` code**: broken wiring (MUNet-old only), hard-coded layer map (`:80-84`), silent skip, interpolation of mismatched shapes, CPU `requires_grad` zero (`:113`). Item 11 keeps only the idea.
- **A-DISTS** (`C/adists_loss.py`): bare `except` switches local statistics to global ones (`:143,:279`). Sample std on 1-element windows gives NaN (Codex probe). No zero-total guard on the entropy weights (`:220`). Deprecated `pretrained=True`, windows stored as `nn.Parameter`. Its SR benefit is unverified. Revisit only with a reference-validated rewrite.
- **`gan_loss.gradient_penalty_loss`**: norm over channels only (`:247`), not per image. `MultiScaleGANLoss` is not needed.
- **`focal_frequency_loss.py`**: same as `T/ff_loss.py` (`.item()` asserts, ×50). No fix. **`ncc_loss.py`**: same G5.2 reshape bug.
- **HSLuvLoss** (`C/basic_loss.py:403-405` mask `y_lightness > eps - 1` is always true, asymmetric hue), **ColorLoss / LumaLoss** (LumaLoss keeps the Y² bug; covered by item 2), **AverageLoss, BicubicLoss** (rebuilds `v2.Resize` per call), **PSNRLoss** (device hack), **FFTLoss, CosimLoss** (`round(decimals=20)` no-op): trivial, buggy or duplicative.
- **HFEN** (`C/hfen_loss.py`): kernel rebuilt per forward. The high-frequency term overlaps GV, wavelet and FF. If it is ever wanted, use a LoG buffer applied once to `pred − target` (the op is linear).
- **Checkerboard loss**: O(scale⁴) memory pairwise diffs and speculative benefit. Revisit only if checkerboard artifacts are observed (then use deviation from the cell mean).
- **`laplacian_loss.py`** (no prefilter, aliasing; `T/msswd_loss.py` has `GaussianPyramid`), **TV / adaptive-block TV** (erodes texture; the adaptive factor sits in (0.5,1)), **`dynamic_loss_scheduling.py`** (905 lines, magnitude-based reweighting, non-stationary objective), **ContextualLoss, FLIP, LineDistiller, PerceptualAnime, AESOP, BCEDice, ModelAsLoss, contrastive**: out of scope or niche.
- **`loss_util.weighted_loss` / `weight_reduce_loss`**: no consumer. The all-zero mask divides by zero, and it uses the private `F._Reduction`.
