## Deferred (feature value, but not now)

- **pyvips region decode** (C `data/transforms.py:214-274`, `utils/img_util.py:330-335`). Partial win for large GT only. New system dependency. Buffers are read as uint8 unconditionally (16-bit PNG breaks). ICC behaviour unverified. Revisit only as an optional lazy-imported `io_backend="vips"` after a measured I/O bottleneck. (Fable: optional later; Codex: do not port.)
- **Modern codec mixtures (WebP/AVIF/HEIF)** (C `models/paragon_otf_degradations.py:39-95`). Take the feature only, and only if the deployment data shows those artifacts. Do it on the uint8 crop in the dataset worker (`cv2.imencode(".webp")`), validate codec availability at startup, and keep fast DiffJPEG as the default. Never per-sample GPU→PIL→GPU inside `feed_data`. (both)

## Do not port

- **C `data/prefetch_dataloader.py:17-487`** (`WorkerHealthMonitor`, `RobustPrefetchGenerator`, `PrefetchDataLoader`, `CPUPrefetcher`, the `CUDAPrefetcher` error path). Worker exceptions are swallowed and `next()` is called again on a dead iterator. Batches come back as `None`. The "timeout" cannot interrupt `next()`. `put()` can block forever. A fallback `DataLoader` is built on every `__iter__` and loses the sampler semantics. The health monitor always reports healthy. It has no `record_stream` fix. (both)
- **C channels_last collate and pinning workaround** (`data/collate_functions.py:40,62`, `prefetch_dataloader.py:431`). It breaks on rank-3 kernel tensors, and the lambda cannot be pickled under spawn. If channels_last is wanted, convert image tensors on GPU after transfer. (both)
- **C `ThreadPoolExecutor` path helpers and the meta/LMDB wrappers** (`data/data_util.py:128-139,196-203,234,327-330`). `map` over key strings gives `l_path`/`g_path`, and it truncates at the shortest iterable. `PairedImageDataset:66,97` bypasses the file client. `RealESRGANDataset:55` repeats `"gt"` client keys. `file_client.py:88,106` uses `zip(strict=False)` and ASCII key encoding, a regression from T's UTF-8. (both)
- **C `utils/lmdb_util.py:96`** LMDB writer: worker exceptions are never collected, it optionally buffers the whole dataset, and publishing is not transactional. (Codex)
- **C `models/realesrgan_model.py` synthesis pipeline as a whole** (`:65`, `:95-402`, `:505+`). The classic two-stage config is largely unused (`kernel2` and `jpeger` are initialised but unused), `:65` references undefined symbols, the `_apply_*` helpers are per-sample CPU round trips, and config is probed with `hasattr`. Its OTF queue (`:403`) shuffles and copies whole queues, adds redundant clones and hard-codes CUDA, so it is no better than T `models/otf.py:38`. (both)
- **C `models/paragon_otf_degradations.py`** (lens distortion, rolling shutter, motion blur, chromatic aberration, video codecs, block/banding/ringing, oversharpen). Motion blur samples even kernels and grows the image (5×5 to 6×6). Lens grids swap x/y, and zero strength is not the identity. Chromatic aberration hard-codes a sub-pixel 1.001 (a near no-op). Video codecs write to `.png`, failures are discarded silently. "Block artifacts" are scalar quantisation inside Python 8×8 loops, and oversharpen is a self-described placeholder box blur. Geometric warps would also need a GT-alignment policy that does not exist. (both)
- **C `utils/rng.py:11-23`** raise-on-reinit, mandatory seed, epoch-invariant worker seeds (see #2). (both)
- **C `ops/batchaug.py:228-304` ResizeMix and `:445-470` `up()`**: H/W swap, bound typo, square-only. Rewrite these from T's side instead (see #3). (both, verified)
- **C `data/transforms.py:197`** list crops sample separate coordinates per pair, which breaks T's shared-coordinate contract. **C `transforms.py:277-410` `augment*`** has the same semantics as T's `basic_augment`. (both)
- **C `utils/img_util.py:107-125` `img2float32`**: casts before checking the dtype, so uint8 128 becomes 1.0. **C `tensor2img` `to_bgr` on 2-D** arrays: broken. (Codex, verified)
- **C `data/degradations.py` wholesale**: it is T's file retyped, minus T's `skewed` kernels. Only `:465` (#10) and `:958-1021` (#11) are worth taking. `:791` keeps the same per-image unique-value Poisson work. While there, delete T's stray `@staticmethod` on the module functions (`degradations.py:24,70`). (both)
- **C `data/dynamic_dataloader_wrapper.py`** (VRAM-driven mid-epoch batch and patch resizing via shared ctypes) and **`data/realesrgan_paired_dataset.py`**: scope creep, outside H2. (Fable)
- **C `utils/diffjpeg.py:509-514` quality loop**: identical to T's bug (in-place mutation, B syncs, non-finite at q=100). Replaced by #9. (both)

## Summary

The competitor genuinely fixes these target defects: loader construction and defaults (G6.1/G6.2/G6.8), the worker RNG design (G6.3, after removing its epoch-replay and re-init bugs), scale-aware augmentations (G6.4, mixup/cutmix/cutblur only), the meta_info LQ filename (G6.7), `tensor2img` (F.2), the CPU sampler, and device-agnostic DiffJPEG.
Features worth adding with today's behaviour as the default: configurable kernel ranges, crop size and multi-folder GT; antialiased resize-mode lists; `blur_prob`; a correctly implemented clean pass-through; `img2tensor` normalisation.
It fixes neither `CUDAPrefetcher` stream lifetime (`record_stream`), the DiffJPEG q=100 and in-place problems, nor OTF queue efficiency. Those remain target-side work.
Suggested order: 1, 2, 5, 4, 7, 8, 9, then 3 (needs a unit test), then 6, 10-13, then 14-15.
Not verified: no GPU, DDP or throughput run. The probes cited (C key bug, `quality_to_factor` equivalence, lanczos sanity, mixup identity, ResizeMix failure, 0-worker loader errors) were CPU-only and come from the two source reports. The code re-reads above were static.
