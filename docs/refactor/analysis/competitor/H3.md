## Disputed claims and how they were settled

| Claim | Who | Verdict (evidence) |
|---|---|---|
| C AMP policy is correct | Fable | **Wrong.** C `sr_model.py:79-83` falls back bf16 to fp16 on unsupported GPUs, but `sr_model.py:188` enables the scaler from the original `opt.amp_bf16`. The result is fp16 with no scaling. Codex is right. |
| C D loss uses the D weight | (implicit) | **Wrong.** C `sr_model.py:776-781` multiplies the D loss by `cri_gan.loss_weight`/`get_current_weight` (the generator weight). `gan_loss.py:20-21` says the weight is "only for generators" and is always 1.0 for D. Codex is right. |
| `AveragedModel(use_buffers=True)` fixes stale EMA buffers (F.1) | Fable | **Wrong as a fix.** torch 2.9.1 `swa_utils.py:307-311` copies live buffers on every `update_parameters` when `use_buffers=False`, and init deep-copies the module. Averaging buffers instead of copying them is a policy choice, not a repair. Remove the F.1 tag. |
| C `current_iter` is a clean step counter | Fable | **Partly.** C `train.py:597-600` increments `current_iter` on the *last* micro-batch of a window, so micro-batches 1..k-1 see step `n` and the last one sees `n+1`. Iteration-keyed schedules (`gan_active`, weight) can change inside one window. Use a stable window index (Codex). |
| C interrupt decrement is off by one | both | **Confirmed.** C `train.py:993-995`: with `apply_gradient=False`, `current_iter` already equals completed steps, so the decrement mislabels the checkpoint. |
| C `check_resume` validates resume paths | Fable | **Buggy.** C `misc.py:150-158` has no `break`: if both `net_g_ema_N` and `net_g_N` exist, `pretrain_network_g_ema` ends up pointing to the live `net_g` file. Port only "raise if missing", not the search loop. |
| C seed handling | Codex | **Confirmed.** C `options.py:172` `if not opt.manual_seed` treats seed 0 as absent. |
| T seed implies deterministic | Fable | **Confirmed.** T `options.py:193-213`: any explicit seed turns on `use_deterministic_algorithms`, `cudnn.benchmark=False` and `fill_uninitialized_memory=True`. |
| T `fast_matmul` | Fable | **Confirmed.** T `train.py:342-346` uses `"medium"` and `allow_fp16_accumulation=True`. |
| C has atomic saves | neither | **Confirmed absent.** C `base_model.py:437,763` writes straight to the destination file, and its retry loop reports a success on the 3rd attempt as a failure. |

Other target facts I checked: T `image.py:607-616` runs D in `eval()` and under `inference_mode` for the G-side pass, so G gets **no adversarial gradient**. T `image.py:990-1003` saves the EMA as `net_g` and the D-EMA as `net_d`, so live G/D are lost on resume. T `image.py:149-153` enables the GradScaler for bf16. T `base.py:551-552` assigns the `None` return of `dist.reduce` and calls `print`. T `base.py:164` compiles with `max-autotune, dynamic=True` inside `model_to_device`, before pretrained weights load at `image.py:50-68`. T `train.py:227-229` loads state with `map_location=cuda` and no `weights_only`. T `logger.py:143` divides the already-divided iteration by `accumulate` again. T `base.py:462-475` calls `state_dict()` on the SF optimizers before `eval()`.

## Do not port

- **C D-update block as a whole** (`sr_model.py:738-786`). It runs only on the `apply_gradient` micro-batch but still divides by `accum` (probe: grad 3.0 vs 2.0), and it applies the G GAN weight to D (`:776-781`, against `gan_loss.py:20-21`). Take the pattern from #1 only.
- **C AMP scaler enablement** (`sr_model.py:188`). It reads the original `opt.amp_bf16`, so after the bf16→fp16 fallback it runs fp16 unscaled. Use #7.
- **C skip flags as an optimizer-state contract** (`sr_model.py:575`, `base_model.py:370`). The persistent D skip flag from `adaptive_d`, inactive-GAN bypass without a fresh result, and warmup ignoring skips. Replaced by explicit per-window outcomes (#8).
- **`adaptive_d`** (`sr_model.py:565-576`, `base_model.py:55-58`). It compares a tensor in an `if` (per-iteration sync), uses a threshold that is a ratio to its own EMA, does not checkpoint its state, and feeds the flawed skip flags. Low value, medium risk. Revisit after #1/#8 if GAN instability shows up.
- **Resume filename search and broad canonicalization** (`misc.py:150-207`, `base_model.py:540-559,612`). No `break` (the EMA path gets overwritten by `net_g`), D discovery recognizes only `ganloss`, the extra fallback key check runs after extraction, and the 0-match branch is unreachable. Strict resume uses exact paths (#5).
- **C counter arithmetic** (`train.py:597-600` late increment, `:993-995` interrupt decrement). Both are wrong (see #2/#11).
- **Checkpoint retry loops / any assumption of atomicity** (`base_model.py:437,763`). These are direct writes, and a success on the 3rd attempt is reported as a failure. Use #4.
- **Automations, dynamic VRAM batch/patch, "automatic OOM recovery"** (`train.py:369-486,757-852`, `base_model.py:86-89,891-1101`). They classify any error containing `"CUDA"`/`"allocate"` as OOM, do no rollback of grads/scaler/counters, clear `train_data` and continue without fetching, and rebuild the DataLoader from private attributes.
- **Crash checkpointing** (`train.py:984-1008`). It saves possibly NaN/inconsistent state and exits 0.
- **"Enhanced" MessageLogger and stats** (`logger.py:64-769`, `sr_model.py:1232-1302`, `train.py:875`). It pops `time` so the throughput branches are dead, uses substring heuristics, a fake `stability_score`, duplicate TB tags, `.item()` every step, and gradient norms recomputed after `zero_grad`.
- **Logger path sanitizer / fallback dirs** (`logger.py:899-1053`). It rejects `:` (Windows drive paths) and `..` after normalization, writes probe files, has no rank-0 guard on `"w"` handlers, and adds debug `print`s (`train.py:303-326`).
- **`Config` global singleton and `opt.contents`** (`config.py:19`, `redux_options.py:920`). It keeps the first config forever. Take only the caching idea (#12).
- **W&B rewrite** (`logger.py:778-800`). It duplicates T's TB-sync integration and passes a Struct as `config`.
- **`ema_pytorch`, `ema_switch_iter`, `update_model_with_ema_every`** (`sr_model.py:223-238`). New dependency, a CPU `.step` hack, and EMA→live swaps are algorithm changes. `use_buffers=True` is not a fix for F.1 (see the correction above).
- **`torch.cuda.set_per_process_memory_fraction(1.0)`** (`train.py:271`, a no-op) and **`set_sharing_strategy("file_system")`** (`train.py:12`, prone to leaks).
- **Loss-wrapper dispatch** via `hasattr(loss,"loss_module")`/`isinstance` chains, a second MoA augmentation for D (`sr_model.py:489-496,525-633`), and the `lq_target` negative-weight hack (`:510-523`). This belongs to the loss area and must not leak into the step.
- **Validation OOM auto-tiling** that mutates `opt.val.tile_size` and continues with stale `self.output` (`sr_model.py:1029-1048`). Out of H3; flagged for the validation area.
- **Rank-0-only validation through the live DDP wrapper** (`sr_model.py:974`). Not a distributed fix.
- **Template diffing machinery** (`options.py:27-54,246-427`), spandrel/ESRGAN special-casing (`base_model.py:583-598,694-704`), and floor-division `iter_per_epoch` (`train.py:131-139`).

## Suggested order

1. #6 → #5 → #3 → #4: load/compile order and strict loading first, then layout and complete atomic state.
2. #2 + #1 + #7 + #8 together. They change step semantics, so validate with one GAN smoke run with accum=2, checking D grad equals the full-batch mean, G gets adversarial grad, and the scheduler/EMA skip on overflow.
3. #9, #10, #13 (logging), then #11.
4. #14, #15 (small policy changes), #12 staged, #16/#17 optional.
